# Mentora Learning Centre — MVP

A bilingual (English / தமிழ்) tuition-centre website, student portal and admin system for Mentora, Negombo.

- **Public site:** Home, Courses, Teachers, Join a Class (free trial), Teach With Us, Contact, Privacy
- **Student portal:** classes, fees and statements, bank-transfer payments, attendance, notices, recordings, profile
- **Teacher panel (v2):** dashboard, timetable (view all, request changes), own classes and attendance, recordings/resources (admin-approved), earnings, reviews, profile
- **Admin:** dashboard with charts, approvals inbox, feedback & reviews, timetable, enquiries, teacher applications, teachers, subjects, classes, students, enrolments, attendance, fees, payments, receipts, settlements, teacher finance, content, reports, settings
- **Installable PWA:** works offline (offline page and form drafts) and updates itself

👉 **To go live, follow [`BACKEND_SETUP_TODO.md`](BACKEND_SETUP_TODO.md) step by step.**
👉 **To understand every page, the backend and upgrade ideas, read [`docs/PROJECT_GUIDE.md`](docs/PROJECT_GUIDE.md).**

## Run it in 30 seconds (demo mode)

```bash
cd mentora
python3 -m http.server 8080      # Windows: py -m http.server 8080
```
Open <http://localhost:8080>. Demo logins (password `demo1234`): `admin@mentora.demo`, `cashier@mentora.demo`, `teacher@mentora.demo`, `student@mentora.demo`.

Demo mode runs **automatically** while `js/config/supabase.js` still has the `YOUR-...` placeholders. The data lives only in your browser (localStorage). Use "Reset demo data" on the login page or in Admin → Settings to start over.

## Tech stack (as required by the spec)

| Layer | Choice | Why |
|---|---|---|
| UI | HTML5, CSS3, **Bootstrap 5.3** | No build step; easy for a junior dev to edit |
| Logic | **Vanilla JavaScript ES modules** | `import`/`export` works natively in browsers; no React/Vue/Tailwind |
| Data | **Supabase** (Auth, PostgreSQL, RLS, RPC functions, Storage) | The database itself enforces security and money rules |
| Hosting | **Cloudflare Pages** | Free, fast in Asia, reads `_headers` for security/caching |
| Offline | Service worker + Cache Storage + IndexedDB | Network-first pages, offline fallback, saved drafts |
| Messaging | WhatsApp click-to-chat (`wa.me`) with pre-filled text | No paid API needed |

## Key decisions (explained)

1. **Business rules live in the database, not the browser.** Anything involving money or access (charging sessions, the admission fee, verifying payments, receipts, approvals, commission) is a PostgreSQL function in the `004a`–`004d` migration files. The browser only *asks*, and the function checks the user's role itself. Someone who edits the JavaScript in their browser still can't approve themselves or delete a payment.
2. **Row Level Security on every private table.** A student's login can only read rows where `student_id` is their own. Anonymous visitors can only read active subjects, public classes and approved teacher profiles (through `get_public_teachers()`, which never returns phone numbers, bank details or documents).
3. **Money is never deleted.** Triggers block `DELETE` on payments, ledger, receipts and the audit log. Mistakes are fixed with **reversals**, which are new rows that cancel the old ones, so the history always adds up.
4. **"Receipt sent" ≠ paid.** A student's bank-transfer payment starts as `pending` → `receipt_sent`. Only an admin's **verify** (with the bank reference) makes it count, allocates it to charges and issues a unique receipt number.
5. **Trials are free by design.** Attendance for a trial enrolment is stored as `trial` with `is_trial = true`, and the charge logic skips it. Unique indexes make a duplicate session charge or a second admission fee impossible.
6. **Codes are generated by the database.** `MA-0001` (student), `MT-001` (teacher), `MMPE-001` (Mentora + Maths + Physical + English medium), and receipt `MR-2026-000001` come from a locked counter table, so two people saving at once can't get the same number. Codes can't be edited afterwards.
7. **Demo mode mirrors the database.** `js/services/demo/demo-rpc.js` implements the same functions in JavaScript so the whole app can be explored before Supabase exists. In live mode it isn't loaded at all.
8. **Generated HTML.** Every page shares the same `<head>`, header and footer. Instead of copying them 30 times, `tools/build_html.py` writes them. Edit the template, then run the script.
9. **PWA safety.** Pages are **network-first** (always fresh when online), static files are cache-first with a versioned cache, and Supabase/API responses are **never cached**. A new service worker downloads everything before taking over, and the page only reloads when no form has unsaved changes.
10. **WhatsApp is a convenience, not proof.** Forms save to the database first, then offer a pre-filled WhatsApp message. We record only "WhatsApp opened", never "message sent".

## Commission and tax (summary)

- First eligible month for a teacher: **0%** commission for their first **20** eligible students; otherwise **5%** of eligible *collected* class revenue (configurable in Settings).
- Admission fees and reversed/refunded money are excluded.
- Withholding tax is a **separate** statutory line, off by default. Confirm the current IRD rules with an accountant before enabling it.
